# FlowTrail 贡献与设计说明

## 功能与改动范围

- 新增问卷星页面：链接白名单与输入约束、资料和答案映射、提交选项、任务状态、运行及浏览器入口。
- 新增任务生成器：将结构化输入转换为任务请求，明确缺失信息、人工处理和问卷不可用三类终止条件。
- 接入现有浏览器会话与任务 API；启动期间禁用重复创建，失败时保留填写内容。
- 修正本地可选诊断接口的特定 403 被误报为身份失效的问题，真实鉴权错误仍正常报告。
- 调整工作台主题、导航、发现页与项目品牌，提供 FlowTrail 标识及文档入口。
- 提供固定镜像的本地部署配置、百炼模型注册、中文演示问卷与集成验证脚本。
- 新增 URL 运行引用与刷新恢复，查询失败不会重建任务；填写资料不进入 URL。
- 将 Agent 评测拆分为模型状态、DOM 字段观测、提交回执三层，按 case ID 隔离证据，严格核对缺失信息原因。
- 新增默认分支的独立 CI，验证场景测试、评测器负例、夹具服务、文档链接和生产构建。

- 新增独立 FastAPI 编排服务：SQLite 唯一约束、请求摘要、持久化阶段、只读恢复、取消确认和受保护的会话释放。

## 请求路径与取舍

前端校验用户输入并生成任务指令，先生成 operation ID，再通过 FlowTrail 编排服务创建 60 分钟会话和任务。服务端在每次外部创建前记录阶段；响应丢失时通过精确标题和会话引用查找原任务，不重新创建。前端轮询 operation，提供运行、浏览器、取消和关闭入口。模型凭据由 Skyvern 后端管理，填写内容进入其任务记录。详见[第二轮任务生命周期](../flowtrail/lifecycle.md)。

使用现有执行器可以保留截图、运行历史和会话查看能力，避免引入第二套浏览器进程。代价是执行效果依赖模型和页面结构：默认不提交是指令约束，而不是动作级授权机制。更强的提交保护需要后端动作拦截与用户确认协议，当前未实现。

每次启动使用独立会话，避免复用已结束任务会话时遇到占用状态。创建结果未知时不自动重发上游创建；前端持有原请求时可以使用同一编号重发给编排服务。没有唯一匹配的任务时仍需检查 Runs。

## 测试证据与限制

- 单元与组件测试覆盖 URL / 输入校验、任务生成、页面状态及鉴权诊断回归；命令见根 README。
- 本地集成测试覆盖入口、两页填写、文本、下拉、单选、多选与提交结果。
- 提交测试核对本次 case 的回执数量及全部字段；只填写测试核对最终页、DOM 字段和零回执，包含单选、多选及确认框。
- 缺少必填邮箱时观察到 `MISSING_INFORMATION` 终止结果。
- 未验证真实问卷星的矩阵、评分、复杂联动及登录验证码处理；没有规模或成功率基准测试。
- 本机未安装 pre-commit，未完成全仓 pre-commit 检查。定向测试和生产构建不能替代全仓后端回归。

## 求职展示建议

可描述为：“开发中文问卷自动化工作台，实现结构化资料到浏览器任务的转换、状态追踪和人工接管入口；通过本地多页问卷验证填写、提交与缺失信息终止流程。”

面试演示优先使用虚构资料和本地夹具，展示输入校验、模型执行记录、回执核对及失败处理，并说明上述功能边界与限制。

## 结果评测与报告

新增执行报告白名单导出与三场景重复评测，区分模型状态、DOM 字段和真实回执；汇总保留全部计划尝试、失败类别及墙钟耗时，源码哈希记录未提交代码的实际版本。实现与边界见[第三轮说明](../flowtrail/evaluation.md)。这是本地场景评测能力，不等于跨站成功率或生产性能基准。

面向 AI Agent 岗位，可围绕以下实际工作展开，而不要只介绍“接入大模型自动填表”：

- 定义业务成功标准，用独立 case 隔离 DOM 观测和提交回执，识别执行器报告完成但字段仍为空的假完成。
- 实现重复评测与失败保留，记录场景版本、源码哈希、配置来源及耗时；不剔除失败或把小样本通过率包装成跨站基准。
- 将执行报告与业务核验分开，使用鉴权、组织隔离和字段白名单导出，保留未知状态而非猜测成功。

面试时可以展示首批真实失败及后续定向复测，解释为什么单元测试通过仍不能证明 Agent 任务成功。公开记录和具体数字见第三轮说明；不要声称已实现浏览器动作层的强制提交拦截或生产级泛化。
