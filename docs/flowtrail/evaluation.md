# 第三轮：执行报告与可重复评测

这一轮补齐“如何判断 Agent 做对了”的证据链。普通任务报告与本地评测报告分别说明自己的证据来源，不把执行器的 `completed` 当作字段正确或提交成功。

## 产品中的执行报告

问卷任务创建后，在页面点击“查看执行报告”，可刷新并导出 JSON。刷新原 operation 链接后仍可查看。接口为 `GET /v1/operations/{operation_id}/report`，沿用调用者鉴权与组织隔离；读取报告不会创建任务。

报告 schema v1 包含 operation/run/session 引用、执行器状态、起止时间、执行耗时、受限错误类别和独立核验状态。未取得独立字段与回执证据时，明确显示“未独立核验”。运行未结束或时间无效时耗时为 `null`，用量接口没有提供的数据也为 `null`，不填写猜测成本。

导出使用白名单字段，不包含 prompt、用户答案、自由文本错误、模型输出或截图链接。运行引用仍属于本地实例元数据，导出并不等于匿名化审计。普通报告不会读取本地评测文件，避免把另一场景的验证结果错误关联到用户任务。

## 小规模评测集

数据定义见 [questionnaires.json](../../skyvern-frontend/scripts/evals/questionnaires.json)。这是固定两页本地问卷的三种任务，使用虚构姓名和 `example.com` 邮箱。

| 场景 | 预期行为 | 独立观测 |
| --- | --- | --- |
| fill-multiselect | 填到最后一页，停在提交前 | 全部字段与多选匹配，零回执 |
| submit-alternative-values | 使用不同姓名、职业、参加方式及兴趣，提交一次 | 全部 DOM 字段和唯一回执均匹配 |
| missing-required-email | 发现必填邮箱缺失后停止 | 结构化错误指出邮箱，DOM 邮箱为空，零回执 |

运行前按[快速开始](quickstart.md)配置模型并启动服务，确保当前代码已挂载到 form-demo 与 flowtrail。以下命令会产生真实模型用量：

```bash
cd skyvern-frontend
# 可选：为本次环境注明配置标签；它是操作者声明，不是提供商的实测版本证明。
FLOWTRAIL_EVAL_MODEL_LABEL='your-configured-model' node scripts/evaluate-questionnaires.mjs 2
```

参数是每个场景的重复次数，范围 1–10，默认 2。默认共 6 次，串行执行，每次新建 operation 和独立 case。可在次数后传入一个场景 ID，进行定向复测，例如 `node scripts/evaluate-questionnaires.mjs 2 fill-multiselect`。每次还验证重复创建/重放引用不变、内容冲突返回 409、恰好一个关联任务以及会话关闭确认。

结果写入 `artifacts/evaluations/<suite_id>/`：

- `summary.json`：运行环境、Git 基线及工作区是否有改动、相关源码 SHA-256、所有计划尝试、分类和耗时分位数。
- 每次尝试的 `attempt.json`：发起创建前落盘，响应丢失后仍可查原 operation。
- `<mode>-latest.json`、`<run_id>.json`：资源引用和执行器原始结果。
- `<run_id>-verification.json`：独立 case 观测、回执、逐项检查和失败原因。
- `execution.log`：该次运行日志。
- `execution-complete.json`：终态证据采集及会话释放校验已结束；缺少它时不能把字段核验通过当作整次通过。

`passed` 必须同时满足脚本退出成功和证据核验通过。`evidence_failed`、`execution_error`、`timeout`、`missing_evidence` 分开统计。基础设施异常或超时会停止后续调度，保留未完成的 `pending` 行（可由 started_at 区分尚未启动与中断后未记录终态）；不能在创建结果未知时自动换一个请求继续。先查询保存的 operation，再决定如何处理原任务。

通过率分母是本次**全部计划尝试**，失败和未执行项不会被丢弃。耗时是每次尝试从启动到退出的墙钟时间，包含任务创建、模型执行、验证与资源释放；p50/p95 使用 nearest-rank，包含成功和失败的已结束尝试，未执行项没有耗时。6 次运行的 p95 只是样本最大值，不能解释为生产延迟承诺。

可将 JSON 汇总转成不含原始答案的 Markdown 表格：

```bash
node skyvern-frontend/scripts/render-evaluation.mjs artifacts/evaluations/<suite_id>/summary.json
```

上述命令在仓库根目录执行，生成同目录 `report.md`。先核对摘要，再用于项目展示。

## 可证明的范围

评测证明固定夹具上这几种行为及工程协议是否满足断言。它不能证明真实问卷星、跨站泛化、矩阵/复杂联动、验证码、生产并发或大规模成功率。缺失信息场景只验证停止、邮箱未编造和未提交，不宣称其余字段全部正确。

评测启动时通过组织默认模型与自定义模型 API 记录配置快照，只保存模型名、提供商及有限参数，不保存密钥、服务地址或额外请求头。无法解析时明确记录 unavailable/unresolved，不猜测默认模型。这个快照不等于逐次调用的实际路由证明。另可填写操作者模型标签。当前 Run API 不提供完整的模型路由、token 和价格快照，因此这些结果不能作为严格的模型间成本对比。Git commit 之外另外记录源码哈希，避免把工作区改动误记为已提交版本。原始结果留在忽略的 artifacts 目录；公开材料只应使用人工核对后的摘要。

## 无模型回归

评测器覆盖假完成、错字段、错选项、错回执、串 case 和缺失信息误判；汇总器覆盖失败与 pending 分母。后端覆盖报告白名单、未知耗时和跨组织访问；前端覆盖按需加载、失败重试、未核验标识及 JSON 下载。命令见[验证指南](testing.md)。

## 2026-10-24 实测记录

原始提示词下执行 3 场景 × 2 次，得到 **5/6 通过**。这是固定夹具的小样本结果，不作为通用成功率。完整机器可读摘要含源码 SHA-256：[首批摘要](evaluation-results/2026-10-24-baseline.json)。摘要中的 verification 相对路径指向本地 suite 产物，原始运行数据未随仓库公开；读者可运行脚本重新验证，不能仅凭公开摘要独立复验历史执行。

| 场景 | 第一次 | 第二次 |
| --- | --- | --- |
| 只填不提交 | 失败，54.16 秒 | 通过，95.99 秒 |
| 替换资料后提交 | 通过，74.61 秒 | 通过，84.08 秒 |
| 缺少邮箱 | 通过，50.27 秒 | 通过，281.00 秒 |

失败 run `tsk_589061234764485512` 的执行器状态为 `completed`，但第二页的介绍、演示确认、参加方式及兴趣没有填写。评测器通过实际 DOM 拒绝这一“假完成”，并验证没有提交回执。原始失败不会被后续复测覆盖。

较慢的缺失邮箱 run `tsk_589062772362778364` 最终产生正确的 `MISSING_INFORMATION` 错误，邮箱保持空白且没有提交，但耗时显著高于第一次。这表明正确结果之外仍存在停止效率问题。首批墙钟耗时 p50 = 74.61 秒、p95 = 281 秒（n=6，nearest-rank）。

在首批运行过程中只读检查配置 API，组织默认配置解析到 `qwen3.5-plus`（openai_compatible）。首批摘要当时尚未自动记录模型配置，因此保留原始 `not_recorded`，不回填为逐次执行的模型证明；后续评测已加入配置快照白名单。

针对跨页提前完成，任务指令新增两条明确条件：翻页后重新观察并填写新页面；看到提交按钮不代表填完，最后一页的可见题目完成核对之后才允许宣布完成。这仍属于模型指令约束，不是执行器层的确定性完成拦截。
